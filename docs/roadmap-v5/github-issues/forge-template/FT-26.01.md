**Repository:** `forge-template`

## Outcome

Measure composition cost and approve test budgets with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. `create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

Matrix growth has outpaced an explicit runtime budget; the review's 5,761 cases and timings are observations, not permanent constants.

## Proposed resolution

Measure representative current CI runs and define evidence-based fast, exhaustive and independent-client tiers.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Record valid and rejected composition counts, deterministic enumeration, per-job wall time, memory where useful, runner image and cold/warm cache conditions.
- [ ] Measure several representative runs and identify the dominant cost; keep the baseline tied to exact commits.
- [ ] Approve numeric warning/failure thresholds and treatment of runner noise; justify the chosen limits rather than guessing them.
- [ ] Map every current safety/compatibility guarantee to a tier; full accepted-composition coverage remains mandatory before release.
- [ ] Define change-sensitive PR escalation and scheduled exhaustive checks; preserve existing protected checks until replacement coverage is approved.

## Exclusions

No reduction of exhaustive release coverage or speculative performance rewrite.
