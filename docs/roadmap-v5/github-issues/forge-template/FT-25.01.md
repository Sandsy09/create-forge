## Problem statement

Discovery, validation, rendering, provenance and update planning need separation without exposing private machinery.

## Proposed resolution

Map the public facade and deterministic contracts; approve a private module split and add missing compatibility characterisation.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Inventory exports, signatures, structured error identities, protocol support and import behaviour.
- [ ] Record discovery/order determinism, golden output bytes, provenance digests and update classifications for accepted compositions.
- [ ] Choose private seams without moving destination filesystem, subprocess or merge responsibility into the provider.
- [ ] Add high-value missing facade/independent-client assertions and document any ADR requirement.

## Exclusions

No public exports, protocols, component catalogue or generated-output changes.
