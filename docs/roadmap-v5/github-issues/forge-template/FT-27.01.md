Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

A batch archetype could fit data-science use, but command semantics, inputs/outputs and ownership are unspecified.

## Proposed resolution

Approve a minimal independent archetype contract with an executable example job, configuration/input validation, explicit outputs and useful exit behaviour.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Decide the component ID/name, src layout, entry command/module, input/config format, sample transformation, output location and exit-code semantics.
- [ ] Define rerun/idempotency, overwrite safeguards, failure handling and logging expectations without pretending to provide a workflow engine.
- [ ] Keep generated projects independently runnable with no Forge runtime dependency; classify optional behaviour as capabilities.
- [ ] Record Python support, dependencies, extension points, user stories and explicit acceptance examples in a living contract and ADR.
- [ ] Exclude scheduling, workers/queues, cloud services, databases, retries/checkpoint engines and orchestration integrations unless separately approved.

## Exclusions

No implementation, scheduler vendor commitment, FastAPI or AWS scaffold.
