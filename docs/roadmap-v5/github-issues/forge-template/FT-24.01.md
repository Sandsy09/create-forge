# FT-24.01 — Make the Ubuntu runner baseline and migration deliberate

**Repository:** `forge-template`  
**Priority:** P1  
**Planning baseline:** 21 September 2026

## Outcome

Make the Ubuntu runner baseline and migration deliberate with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. Review observations must be rechecked against the implementation candidate.

`create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

The review reports an ubuntu-latest migration to Ubuntu 26.04 beginning 19 October 2026. The effective runner baseline is currently implicit.

## Proposed resolution

Verify the upstream schedule and image availability, then pin the supported baseline or add a non-blocking 26.04 canary with a documented promotion decision.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Inventory repository workflows and reusable jobs; record the current image and primary-source migration notice before choosing the baseline.
- [ ] Make the supported baseline explicit before the review-reported 19 October date, or revise the date using authoritative evidence.
- [ ] Validate package builds, direct-Copier and engine generated projects, scientific/native dependencies, Git/update behaviour and wheel contents.
- [ ] Separate canary failures from protected release checks; retain SHA action pins, least privilege and the required aggregate gate.
- [ ] Document canary ownership, promotion/rollback criteria and evidence; if the 26.04 image is unavailable, pin a supported baseline and track later validation.

## Exclusions

Generated workflow baseline changes require a separate explicit compatibility decision; do not silently alter user projects.

## Dependencies and blocking requirements
