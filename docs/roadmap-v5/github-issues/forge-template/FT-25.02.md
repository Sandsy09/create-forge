## Outcome

Extract discovery, rendering and update-planning internals with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. Review observations must be rechecked against the implementation candidate.

`create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

engine.py combines multiple responsibilities behind the facade.

## Proposed resolution

Move discovery/validation, rendering and provenance/update planning into cohesive private modules while preserving the supported top-level API.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Keep supported facade exports, call signatures, structured errors and protocols unchanged.
- [ ] Keep deterministic selection/order, output bytes and metadata digests unchanged for existing components.
- [ ] Keep provider planning in memory and client-owned filesystem/Git behaviour out of the provider.
- [ ] Preserve package resources and wheel exclusions; use incremental changes backed by the compatibility baseline.

## Exclusions

No new archetypes or unrelated render-output changes.
