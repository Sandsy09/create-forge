**Repository:** `create-forge`

## Problem statement

ROLLBACK_HINT uses git restore . && git clean -fd even though successful updates stage changes. git restore . does not restore the index; an interrupted rename may also already affect it.

## Proposed resolution

Separate recovery by actual Git state. Document repository-root, clean-start and HEAD assumptions; provide staged recovery with git restore --source=HEAD --staged --worktree ., and require git clean -nd review before optional deletion.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Use real Git repositories to reproduce completed/staged and interrupted updates, including interruptions after git mv and around stage_result; verify index, worktree, additions, removals and renames.
- [ ] Only recommend worktree-only recovery when the index is unchanged; otherwise use HEAD/index/worktree recovery. Cover partial staging and projects with no recoverable HEAD through safe guidance.
- [ ] Run Git commands from the repository root, preview untracked removal and explain that abandoning the update also discards later uncommitted work; never execute recovery automatically.
- [ ] Update CLI hints, lifecycle/update contracts, updates.md, migration.md and the published 0.4.0 release notes consistently; preserve historical ADRs.
- [ ] Tests demonstrate the documented procedure restores the recorded baseline without unintended deletion of ignored/user data; new files are reviewed before cleaning.

## Exclusions

No automatic destructive rollback and no new backup subsystem.
