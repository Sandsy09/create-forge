# CF-25.03 — Reorganise command tests and verify installed compatibility

**Repository:** `create-forge`  
**Priority:** P2  
**Planning baseline:** 21 September 2026

## Outcome

Reorganise command tests and verify installed compatibility with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. Review observations must be rechecked against the implementation candidate.

`create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

Moving production code alone leaves a monolithic test module and may hide packaging/import regressions.

## Proposed resolution

Group tests by command/contract, remove accidental private-module coupling and align living architecture documentation.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Keep existing regression coverage and shared fixtures discoverable; avoid duplicate tests that only mirror new helper calls.
- [ ] Built wheel, plain installation, legacy extra and isolated engine-source commands work with the new package layout.
- [ ] Required fast, Windows, network and end-to-end checks pass against the refactored candidate.
- [ ] Document the module map, stable public entry points and evidence; no release claimed without its normal publication process.

## Exclusions

No public API change or new release obligation solely for file movement.
