**Repository:** `create-forge`

## Outcome

Characterise CLI commands and agree extraction seams with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. Review observations must be rechecked against the implementation candidate.

`create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

Splitting the command module without a behavioural baseline risks prompts, help text, exit codes and optional imports.

## Proposed resolution

Map new/list/update/doctor responsibilities, choose command-oriented internal seams and capture high-value public CLI contracts.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Record command inputs, outputs, prompts, exit codes, config and default behaviour for interactive and non-interactive use.
- [ ] Identify engine-free modules, permitted provider imports and lazy legacy imports; keep isolated engine execution intact.
- [ ] Add missing black-box regressions for failure cleanup, redaction, update safety and public entry points; avoid snapshots of private implementation detail.
- [ ] Approve a bounded extraction sequence and update architecture decision records only where the architecture contract actually changes.

## Exclusions

No public command or provider protocol changes.
