## Problem statement

Git, uv and worker/test subprocesses can decode output using the host locale. Non-UTF-8 Windows environments expose inconsistent behaviour.

## Proposed resolution

Inventory capture sites and implement small engine-free capture/decoding helpers with separate rules for diagnostics, structured protocol output and binary data.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Record every production capture site and relevant installed-test helper, including Git, uv and isolated worker calls.
- [ ] Machine-readable worker/JSON output uses the documented explicit encoding and strict decode/parse failure; malformed bytes cannot silently become valid protocol data.
- [ ] Human diagnostic bytes cannot cause an unhandled decoding error; sanitisation occurs before display, and raw credentials/argv/stderr are never newly exposed.
- [ ] Keep merge-file content binary and preserve timeout, return-code, signal and error behaviour; do not force replacement decoding on file/path data.
- [ ] Add focused malformed-byte and non-ASCII coverage; update the subprocess contract and add an ADR if the public/error boundary changes.

## Exclusions

No broad CLI decomposition; PYTHONUTF8=1 is not the sole fix.
