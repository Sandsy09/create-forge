## Problem statement

The reported failures currently disappear under PYTHONUTF8=1, which does not establish support for the affected environment.

## Proposed resolution

Add a Windows regression using a verified non-UTF-8 interpreter/console setup and the installed CLI; keep a UTF-8 control case.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Record actual interpreter mode and preferred encoding; exercise PYTHONUTF8=0 where supported and do not silently run only the UTF-8 case.
- [ ] Cover non-ASCII paths and human diagnostics, invalid diagnostic bytes, strict worker JSON rejection, Git/uv errors and secret redaction.
- [ ] Reproduce the five reported local failures where fixtures are available and record any unreproduced case explicitly.
- [ ] Run generation/update and installed helper paths with the supported Python matrix policy; Linux and UTF-8 controls remain green.
- [ ] Document supported settings and troubleshooting; no global forced UTF-8 workaround is required for correctness.

## Exclusions

No console redesign or new Python-version support.
