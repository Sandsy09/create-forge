# CF-22.01 — Contain all engine-update filesystem targets

**Repository:** `create-forge`  
**Priority:** P0

## Outcome

Contain all engine-update filesystem targets with the acceptance evidence below.

## Issue context

This work comes from the 21 September 2026 engineering review. Live reconciliation on 21 September confirms forge-template 0.6.0 is published, create-forge PR #186 is merged and CF-21.01 is closed; CF-21.02 and CF-21.03 remain open. Review observations must be rechecked against the implementation candidate.

`create-forge` owns CLI UX, ProjectSpec construction, source isolation, destination filesystem/Git/hooks and error presentation. `forge-template` owns descriptors, manifests, composition, generated content, provenance and in-memory update planning. Data flow: create-forge → ProjectSpec → forge-template discovery/render/plan → create-forge filesystem/Git finalisation.

## Problem statement

Provider plans, rename endpoints and editable generation metadata are joined to the project root without a common client containment boundary. This is an observed validation gap; exploitation has not been demonstrated.

## Proposed resolution

Introduce an engine-free project-relative resolver and preflight the complete update before any project mutation; revalidate at filesystem use. Apply it to normal/degraded updates, metadata access and refresh, rename source/destination, reads, writes and removals.

## Scope

Implement the stated resolution and acceptance criteria in this repository; update affected living contracts in the same PR.

## Acceptance criteria

- [ ] Reject empty/root-only, absolute, drive-qualified (including drive-relative), UNC, traversal and platform-ambiguous targets on every host; define accepted POSIX spelling.
- [ ] Reject escaping final symlinks, symlinked parents and Windows junction/reparse escapes; handle non-existing leaves correctly. State the concurrent-filesystem-mutation threat model and avoid unsupported race-safety claims.
- [ ] Preflight all targets before the first rename/write/delete, including skipped/unchanged entries and tampered recorded targets; dry-run cannot read outside the project.
- [ ] Test normal, degraded, rename, dry-run and tampered metadata paths on Linux and Windows; an outside sentinel remains unread and unchanged, and an invalid late target leaves no partial mutation.
- [ ] Preserve legitimate local edits, conflict handling, lock/provenance lifecycle and existing error codes; sanitise diagnostics and update affected filesystem/lifecycle contracts.

## Exclusions

No provider-side filesystem mutation, catalogue duplication or full module refactor.
