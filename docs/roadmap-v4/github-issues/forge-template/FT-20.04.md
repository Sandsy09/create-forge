# FT-20.04 — Publish and verify the reviewed Streamlit provider release

## Outcome

Provide immutable package and compatibility evidence.

## Issue context

The released provider catalogue contains Library, CLI Application and Data
Science plus Jupyter and Scientific Python. Streamlit is future work. Accepted
cutover contracts are its scheduling gate; the full cutover release is not.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Provide immutable package and compatibility evidence. The current release does
not establish completion of this requirement; it needs the evidence and
ownership checks below.

## Proposed resolution

- Read the accepted predecessor contracts and implement only this issue's
  assigned outcome through the owning repository boundary.
- Add executable evidence for each acceptance criterion and update affected
  living documentation. Stop for a contract decision if required behaviour is
  still unresolved.

## Acceptance criteria

- [ ] Publish the contract-approved compatibility line only after provider
  matrix and protected checks pass.
- [ ] Verify published artefacts, resource inclusion and installation; record
  tag/commit, package bounds, component identity and immutable evidence.
- [ ] Hand off the released provider to the client without claiming
  engine-default cutover or client Streamlit support has already shipped.

## Review obligations

These review criteria apply to this issue's assigned slice; other listed
owners complete the remaining slices. Decision-issue exclusions apply to the
decision itself, not to the entire delivery roadmap.

### FT-ROADMAP-02-AC-08

A reviewed `forge-template` release is published and verified before
downstream adoption begins.

Owners: [FT-20.04](FT-20.04.md).

## Exclusions

- No CLI flags/prompts, client configuration, Git/hook execution or
  destination finalisation in the provider.
- No arbitrary remote component registry or plugin execution; no new shared
  Forge runtime dependency for generated projects.
- No cloud deployment, container orchestration, authentication, database or
  FastAPI surface. No engine-default switch as part of Streamlit delivery.

## Dependencies

- Blocked by [FT-20.03](FT-20.03.md).

Provider adoption must use a reviewed immutable release, never a moving
branch. Local candidate pairing is validation evidence, not publication.
