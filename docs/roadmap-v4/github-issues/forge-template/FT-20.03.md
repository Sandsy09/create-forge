# FT-20.03 — Validate Streamlit generated projects and distributions

## Outcome

Prove locks, checks, applicable build/install, bounded non-serving smoke and
existing-archetype regressions.

## Issue context

The released provider catalogue contains Library, CLI Application and Data
Science plus Jupyter and Scientific Python. Streamlit is future work. Accepted
cutover contracts are its scheduling gate; the full cutover release is not.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Prove locks, checks, applicable build/install, bounded non-serving smoke and
existing-archetype regressions. The current release does not establish
completion of this requirement; it needs the evidence and ownership checks
below.

## Proposed resolution

- Read the accepted predecessor contracts and implement only this issue's
  assigned outcome through the owning repository boundary.
- Add executable evidence for each acceptance criterion and update affected
  living documentation. Stop for a contract decision if required behaviour is
  still unresolved.

## Acceptance criteria

- [ ] Exercise all four accepted compositions across the approved Python
  endpoints: restore committed locks, run canonical checks, applicable
  builds/isolated installs and bounded non-serving smoke.
- [ ] Prove deterministic rendering, safeguards, structured invalid-selection
  failures and no persistent application server.
- [ ] Protect Library, CLI Application and Data Science outputs; audit all
  new wheel/sdist resources and Forge-free generated installations.

## Review obligations

These review criteria apply to this issue's assigned slice; other listed
owners complete the remaining slices. Decision-issue exclusions apply to the
decision itself, not to the entire delivery roadmap.

### FT-ROADMAP-02-AC-05

Generated projects restore from committed lock state, pass their canonical

check without starting a persistent server.

Owners: [FT-20.03](https://github.com/Sandsy09/forge-template/issues/161).

### FT-ROADMAP-02-AC-06

Library, CLI Application and Data Science output remain protected by
regression tests.

Owners: [FT-20.03](https://github.com/Sandsy09/forge-template/issues/161).

### FT-ROADMAP-02-AC-07

Wheel/sdist audits include every new engine resource and no generated project
depends on a Forge package at runtime.

Owners: [FT-20.03](https://github.com/Sandsy09/forge-template/issues/161).

## Exclusions

- No CLI flags/prompts, client configuration, Git/hook execution or
  destination finalisation in the provider.
- No package publication in this issue; its separate release child owns
  publication.
- No arbitrary remote component registry or plugin execution; no new shared
  Forge runtime dependency for generated projects.
- No cloud deployment, container orchestration, authentication, database or
  FastAPI surface. No engine-default switch as part of Streamlit delivery.

## Dependencies

- Blocked by [FT-20.02](https://github.com/Sandsy09/forge-template/issues/160).

Provider adoption must use a reviewed immutable release, never a moving
branch. Local candidate pairing is validation evidence, not publication.
