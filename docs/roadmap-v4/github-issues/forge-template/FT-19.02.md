# FT-19.02 — Define Streamlit composition, compatibility and acceptance

## Outcome

Approve four capability combinations, Python support, bounded smoke validation
and the target provider line.

## Issue context

The released provider catalogue contains Library, CLI Application and Data
Science plus Jupyter and Scientific Python. Streamlit is future work. Accepted
cutover contracts are its scheduling gate; the full cutover release is not.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Approve four capability combinations, Python support, bounded smoke validation
and the target provider line. The current release does not establish
completion of this requirement; it needs the evidence and ownership checks
below.

## Proposed resolution

- Review predecessor decisions and current living contracts, compare
  alternatives and obtain explicit maintainer approval for each unresolved
  design choice in the acceptance checklist.
- Record the accepted choice in a new ADR and update its owning living
  contract; preserve historical ADRs and completed roadmap evidence.
- Reconcile affected implementation drafts, acceptance tests and dependency
  edges before unblocking them. If the contract reveals larger work, split it
  into bounded issues before implementation.

## Acceptance criteria

- [ ] Approve no-capability, Jupyter-only, Scientific-Python-only and
  combined selections, with concrete compatibility and deterministic
  validation requirements.
- [ ] Select supported Python/dependency bounds, applicable package
  build/install requirements, committed-lock restoration and a time-bounded
  non-serving smoke strategy.
- [ ] Choose the concrete provider compatibility line and public-interface
  impacts; identify and add only genuinely required cutover implementation
  dependencies before unblocking FT-20.01.
- [ ] Define provider-first release gates and preview-path adoption if
  cutover is not shipped; do not require full cutover completion merely
  because this is roadmap v4.

## Review obligations

These review criteria apply to this issue's assigned slice; other listed
owners complete the remaining slices. Decision-issue exclusions apply to the
decision itself, not to the entire delivery roadmap.

## Exclusions

- No runtime implementation, generated-content change, protocol increment,
  package version bump or release in this decision issue.
- Do not preselect metadata filenames, merge algorithms, Streamlit layout or
  deprecation dates without the accepted decision.
- No arbitrary remote component registry or plugin execution; no new shared
  Forge runtime dependency for generated projects.
- No cloud deployment, container orchestration, authentication, database or
  FastAPI surface. No engine-default switch as part of Streamlit delivery.
