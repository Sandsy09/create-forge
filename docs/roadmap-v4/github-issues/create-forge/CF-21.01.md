# CF-21.01 — Adopt the released Streamlit provider

## Outcome

Update compatible package bounds and verify generic
interactive/non-interactive discovery.

## Issue context

The released provider catalogue contains Library, CLI Application and Data
Science plus Jupyter and Scientific Python. Streamlit is future work. Accepted
cutover contracts are its scheduling gate; the full cutover release is not.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Update compatible package bounds and verify generic
interactive/non-interactive discovery. The current release does not establish
completion of this requirement; it needs the evidence and ownership checks
below.

## Proposed resolution

- Read the accepted predecessor contracts and implement only this issue's
  assigned outcome through the owning repository boundary.
- Add executable evidence for each acceptance criterion and update affected
  living documentation. Stop for a contract decision if required behaviour is
  still unresolved.

## Acceptance criteria

- [ ] Adopt the immutable Streamlit provider using existing compatibility
  policy; align package metadata, diagnostics and development pairing.
- [ ] Verify generic interactive/non-interactive selection without any
  production streamlit branch for catalogue, validation, composition or
  generated content.
- [ ] If cutover is not shipped, retain the supported engine-preview path and
  plain-install optionality; never expand the Copier registry to expose
  Streamlit.

## Review obligations

These review criteria apply to this issue's assigned slice; other listed
owners complete the remaining slices. Decision-issue exclusions apply to the
decision itself, not to the entire delivery roadmap.

## Exclusions

- No provider manifests, template resources, generated dependencies/tasks or
  copied catalogue validation in the client.
- No package publication in this issue; its separate release child owns
  publication.
- No arbitrary remote component registry or plugin execution; no new shared
  Forge runtime dependency for generated projects.
- No cloud deployment, container orchestration, authentication, database or
  FastAPI surface. No engine-default switch as part of Streamlit delivery.
