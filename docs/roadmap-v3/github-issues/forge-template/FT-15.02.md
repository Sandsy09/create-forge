# FT-15.02 — Define generation provenance and reproducible-update inputs

## Outcome

Specify versioned metadata, output ownership and reproducible old/new render
requirements.

## Issue context

The released baseline is create-forge 0.3.2 with default direct-Copier
generation and an optional, hidden engine preview over forge-template
>=0.4.1,<0.5. Preview generation does not provide engine-native updates. This
draft describes future work, not a shipped interface.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Specify versioned metadata, output ownership and reproducible old/new render
requirements. The current release does not establish completion of this
requirement; it needs the evidence and ownership checks below.

## Proposed resolution

- Review predecessor decisions and current living contracts, compare
  alternatives and obtain explicit maintainer approval for each unresolved
  design choice in the acceptance checklist.
- Record the accepted choice in a new ADR and update its owning living
  contract; preserve historical ADRs and completed roadmap evidence.
- Reconcile affected implementation drafts, acceptance tests and dependency
  edges before unblocking them. If the contract reveals larger work, split it
  into bounded issues before implementation.

## Acceptance criteria

- [ ] Define metadata ownership, schema/version negotiation, effective
  ProjectSpec, immutable provider/component identity and generated-output
  ownership sufficient to reproduce an earlier render.
- [ ] Specify how local edits, added/deleted/renamed files and unavailable
  historical providers are represented or rejected without choosing filesystem
  application inside the provider.
- [ ] Specify secret-free persisted/displayed data and malformed, missing,
  tampered or unsupported metadata handling; reconcile project provenance with
  existing selection/policy provenance.

## Review obligations

These review criteria apply to this issue's assigned slice; other listed
owners complete the remaining slices. Decision-issue exclusions apply to the
decision itself, not to the entire delivery roadmap.

### FT-ROADMAP-01-AC-02

A versioned provider contract defines output ownership/provenance and the

Owners: [FT-15.02](FT-15.02.md), [FT-17.01](FT-17.01.md),

## Exclusions

- No runtime implementation, generated-content change, protocol increment,
  package version bump or release in this decision issue.
- Do not preselect metadata filenames, merge algorithms, Streamlit layout or
  deprecation dates without the accepted decision.
- No arbitrary remote component registry or plugin execution; no new shared
  Forge runtime dependency for generated projects.

## Dependencies
