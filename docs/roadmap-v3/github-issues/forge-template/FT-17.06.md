# FT-17.06 — Publish and verify the reviewed cutover provider release

## Outcome

Record immutable artefacts and the supported client hand-off.

## Issue context

The released baseline is create-forge 0.3.2 with default direct-Copier
generation and an optional, hidden engine preview over forge-template
>=0.4.1,<0.5. Preview generation does not provide engine-native updates. This
draft describes future work, not a shipped interface.

Provider manifests, composition, generated content and in-memory validation
stay in forge-template. Client UX, ProjectSpec construction, staging,
filesystem application, Git/hooks and error presentation stay in create-forge.

## Problem statement

Record immutable artefacts and the supported client hand-off. The current
release does not establish completion of this requirement; it needs the
evidence and ownership checks below.

## Proposed resolution

- Read the accepted predecessor contracts and implement only this issue's
  assigned outcome through the owning repository boundary.
- Add executable evidence for each acceptance criterion and update affected
  living documentation. Stop for a contract decision if required behaviour is
  still unresolved.

## Acceptance criteria

- [ ] Publish only the compatibility line approved by the contract using
  CONTRIBUTING's protected release and dry-run workflow.
- [ ] Verify public wheel/sdist installation, tag/commit identity and
  required engine resources; record immutable evidence and supported client
  bounds.
- [ ] Provide a provider hand-off without asserting that client cutover has
  shipped or closing its integrated validation gates.
