# Feedback and contributions

Questions about the instructions, missing examples, and reports of broken
behaviour help improve Forge. Use the existing GitHub issue forms; you
will need a GitHub account to submit an issue or propose an edit.

| What you want to report | Where to go |
| --- | --- |
| Incorrect instructions or a missing user guide | [Documentation feedback](https://github.com/Sandsy09/create-forge/issues/new?template=documentation.yml) |
| CLI installation, prompts, options, or diagnostics | [create-forge issues](https://github.com/Sandsy09/create-forge/issues/new/choose) |
| Generated code, notebooks, dependencies, or CI | [forge-template issues](https://github.com/Sandsy09/forge-template/issues/new/choose) |
| A new project type or capability | [Template feature request](https://github.com/Sandsy09/forge-template/issues/new?template=feature_request.yml) |
| A correction to the template repository's own docs | [Template documentation feedback](https://github.com/Sandsy09/forge-template/issues/new?template=documentation.yml) |

If you are unsure which repository owns a problem, open an issue in
`create-forge` and describe what you were trying to do. Maintainers can
route it. Search existing issues first so related reports stay together.

For documentation, include the page URL, the unclear or incorrect step,
and what you expected to find. Suggested wording is welcome but optional.
For bugs, include a minimal command, your versions and operating system,
and the relevant error. Remove credentials and private project data.

## Suggest an edit

Every guide has a source-edit link and a documentation-feedback link.
Small wording fixes can go directly into a pull request. New guides should
explain the use case, show runnable commands, describe expected output,
and give readers their next useful action.

Follow the contribution guide for the repository you are changing:

- [create-forge contributing](https://github.com/Sandsy09/create-forge/blob/main/CONTRIBUTING.md)
- [forge-template contributing](https://github.com/Sandsy09/forge-template/blob/main/CONTRIBUTING.md)

## Security reports

Use the repository's private reporting process for suspected
vulnerabilities; do not put them in public issues:

- [create-forge security policy](https://github.com/Sandsy09/create-forge/blob/main/SECURITY.md)
- [forge-template security policy](https://github.com/Sandsy09/forge-template/blob/main/SECURITY.md)
